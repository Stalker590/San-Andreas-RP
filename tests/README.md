# Тестирование фазы 9 (ROADMAP 9.2)

Каталог содержит автоматические и ручные проверки античита, баланса
Zero-Faucet экономики и конкурентного доступа к хранилищам.

## 1. Автоматические проверки

```bash
./tests/run_phase9_checks.sh
```

Скрипт выполняет:

1. **Полную сборку** `./build.sh` и требует `0 ошибок, 0 предупреждений`.
2. **Статические проверки** (`tests/phase9_static_checks.py`):
   * все `.pwn` в Windows-1251 без BOM;
   * ровно 25 стартовых ролей с ID 1..25 и уникальными названиями;
   * ровно 91 предмет с ID 1..91 и уникальными `code_name`;
   * распределение экспортной выручки портов `90% / 5% / 5%`;
   * выплаты шахтёрам и логистике списываются из `reserve_usd` с проверкой остатка;
   * античит перехватывает пакеты `200/203/204/207`, фильтрует флуд, пишет в `audit_logs`, вызывает `BanEx`;
   * в модулях нет `TODO`/`FIXME`/заглушек;
   * файлы DevOps на месте (systemd, cron, logrotate, очистка аудита);
   * пункты `9.1–9.3` отмечены в `ROADMAP.md`.
3. **SQL-инварианты** (`tests/phase9_invariants.sql`), если БД из `.env`
   доступна. Проверяются отрицательные резервы и балансы, уровни розыска,
   дубликаты серийных номеров оружия, осиротевшие хранилища, нулевые лимиты
   и корректность портового спреда. Если MySQL недоступен — проверка
   помечается как `SKIP`.

Код возврата `0` означает, что фаза 9 пройдена.

## 2. Встроенные тесты в игровом сервере

При старте сервера модуль `core/mod_anticheat.pwn` через 1,5 секунды после
`OnGameModeInit` выполняет интеграционные тесты и выводит в консоль строку:

```
[Core/AntiCheat] Тесты 9.2: роли=ОК (0) | предметы=ОК (0) | экономика=ОК (0) |
порты=ОК (0) | мьютексы=ОК (0) | серийники=ОК (0).
```

Тесты проверяют:

* 25 ролей: название, капитал, долг, розыск, точку спавна, предметы и навыки;
* 91 предмет: базовую массу, объём, русское название;
* формулу массы `200 M4 = 5800 г`;
* резервы предприятий и привязку складов;
* 54+ портовые котировки и положительный спред;
* **конкурентный доступ**: 20 раундов по 24 одновременных захвата одного
  `gStorageMutex` — успешным должен быть ровно один захват;
* уникальность 512 сгенерированных серийных номеров оружия.

В игре администратор (уровень 3+) может повторить проверки:

```
/actest   — запустить интеграционные тесты 9.2;
/acstats  — сводка античита: пакеты, нарушения, кики, баны.
```

## 3. Ручные тест-кейсы 25 стартовых ролей

Для каждой роли создайте персонажа и сверьте:

| Проверка | Ожидаемый результат |
| --- | --- |
| Стартовый кэш | Совпадает с разделом 9 `CONTEXT_OF_PROJECT.md` |
| Банковский счёт | Есть у граждан, отсутствует у нелегалов и Сектанта |
| Стартовый долг | `$10,000` только у Опального Пилота Картеля |
| Стартовый розыск | `5` только у Джихадиста-Подрывника |
| Стартовые предметы | Оружие с точным боезапасом, документы, инструменты |
| Лимит веса | `MUSCLE` и бонус роли применяются по формуле `25000 + MUSCLE×35 + Δ` |
| Перки | Отображаются и работают (например, `PERK_NO_WEAPON_LIC`) |
| Точка спавна | Соответствует лору роли, персонаж не проваливается под карту |

Быстрый smoke-тест: создать по одному персонажу каждой роли, выполнить
`/inv`, `/stats`, `/actest`; сервер не должен выдать ни одного предупреждения
античита за 5 минут нахождения в мире.

## 4. Zero-Faucet: проверка замкнутости экономики

1. Пополнить `reserve_usd` предприятия-шахты на `$10,000`.
2. Добыть руду на шахте и сдать её на склад предприятия.
3. Убедиться, что выплата уменьшила `reserve_usd` ровно на сумму выплаты.
4. Опустошить резерв и повторить добычу: руда принимается на склад, но
   денежная выплата блокируется сообщением об отсутствии средств.
5. Переработать руду в сталь на заводе: количество ингредиентов на складе
   уменьшается на объём рецепта, готовая продукция появляется только после
   успешного списания.
6. Экспортировать сталь через порт: выручка делится `90% / 5% / 5%`,
   сумма трёх частей равна стоимости партии (без «лишних» долларов).

Ожидаемый результат: ни один предмет и ни один доллар не появляются
из воздуха; при пустом резерве выплата невозможна.

## 5. Стресс-тест хранилищ (20+ игроков)

1. Собрать 20+ тестовых клиентов на одном сервере.
2. Поставить всех рядом с одним багажником/трупом.
3. Одновременно выполнить `/trunk` (или контекстную клавишу `Y`) и положить
   предмет в хранилище.
4. Повторить 50 циклов «открыть — переложить — закрыть».

Ожидаемый результат:

* одновременно хранилище изменяет только один игрок, остальные получают
  сообщение «Хранилище сейчас используется другим игроком»;
* количество предметов до и после стресс-теста совпадает (нулевой дюп);
* в `audit_logs` появляется ровно одна запись `ITEM_MOVE` на успешную
  операцию;
* `gStorageMutex` освобождается (проверяется watchdog-таймером и `/actest`);
* сервер сохраняет стабильный tickrate, память не растёт.

## 6. Проверка античита (9.1)

| Сценарий | Ожидаемый результат |
| --- | --- |
| Выдача оружия клиентским собейтом | Пакет блокируется, игрок банится, запись `AC_WEAPON_HACK` в `audit_logs` |
| Подмена патронов в клиенте | Пакет `204` блокируется, бан, запись `AC_AMMO_HACK` |
| Телепорт по карте | Перемещение отклоняется за < 250 мс, запись `AC_TELEPORT` |
| SpeedHack / AirBreak | Запись `AC_SPEEDHACK` / `AC_AIRBREAK`, кик или бан |
| GodMode / NOP Damage | Трёхкратное расхождение HP/брони с сервером, запись `AC_GODMODE` |
| Флуд диалогами или командами | Ответы блокируются, запись `AC_DIALOG_FLOOD` / `AC_COMMAND_FLOOD` |
| Серверный телепорт (тюрьма, больница) | Ложного срабатывания нет |

Все инциденты фиксируются в `audit_logs` с типом действия `ANTICHEAT`.
